# Стратегия защиты данных: Data Encryption at Rest and In Transit

## 1. Классификация данных

### 1.1 По уровню чувствительности

| Уровень | Описание | Примеры данных | Профиль риска |
|---------|----------|----------------|---------------|
| **L1 — Критический** | Особые категории ПДн, врачебная тайна | Диагнозы, результаты анализов, медкарты | Критический — утечка приводит к серьёзному ущербу |
| **L2 — Высокий** | Персональные данные (PII) | ФИО, паспорт, СНИЛС, контакты, адреса | Высокий — нарушение ФЗ-152, штрафы |
| **L3 — Средний** | Финансовые и операционные данные | Платежи, договоры, зарплаты | Средний — финансовые потери |
| **L4 — Низкий** | Внутренние данные | Расписание, прайс-лист | Низкий — минимальный ущерб |

### 1.2 По состоянию данных

| Состояние | Описание | Риски |
|-----------|----------|-------|
| **At Rest** | Данные в хранилищах (БД, файлы, бэкапы) | Несанкционированный доступ к серверу, кража носителей |
| **In Transit** | Данные при передаче по сети | Перехват трафика, MITM-атаки |
| **In Use** | Данные в оперативной памяти при обработке | Дампы памяти, side-channel атаки |

## 2. Классификация данных с обоснованием защиты и инструментами

| Данные | Уровень | Состояние | В чём необходимость защиты | Инструменты защиты |
|--------|---------|-----------|---------------------------|-------------------|
| **Медицинские карты (PHI)** | L1 | At Rest | Врачебная тайна (ФЗ-323), особые категории ПДн (ФЗ-152 ст.10) | AES-256 (TDE), изолированная БД, RBAC |
| **Результаты анализов** | L1 | At Rest + In Transit | Врачебная тайна, данные передаются из лаборатории | AES-256, TLS 1.3, API-шифрование |
| **Диагнозы и заключения** | L1 | At Rest | Врачебная тайна, репутационный риск при утечке | AES-256, контроль доступа ABAC |
| **ФИО пациентов** | L2 | At Rest + In Transit | ПДн (ФЗ-152), идентификация личности | AES-256, TLS 1.3, маскирование |
| **Паспортные данные** | L2 | At Rest | ПДн, риск мошенничества при утечке | AES-256, ограниченный доступ |
| **СНИЛС** | L2 | At Rest | ПДн, используется для идентификации в госсистемах | AES-256, токенизация |
| **Контактные данные (телефон, email)** | L2 | At Rest + In Transit | ПДн, используются для уведомлений | AES-256, TLS 1.3 |
| **Адрес проживания** | L2 | At Rest | ПДн, может раскрыть местоположение | AES-256, минимизация хранения |
| **Платёжные данные (карты)** | L3 | In Transit | PCI DSS, финансовый ущерб при компрометации | Токенизация, не хранить CVV, TLS 1.3 |
| **История платежей** | L3 | At Rest | Финансовая информация, налоговый учёт | AES-256, аудит доступа |
| **Договоры с пациентами** | L3 | At Rest | Содержат ПДн и финансовые условия | AES-256, контроль версий |
| **Данные сотрудников (HR)** | L3 | At Rest | ПДн сотрудников, зарплатные данные | AES-256, RBAC (только HR/бухгалтерия) |
| **Учётные данные (логины/пароли)** | L2 | At Rest | Компрометация даёт доступ к системе | bcrypt/Argon2 (хэширование), HSM |
| **Логи аудита** | L3 | At Rest | Доказательная база при инцидентах | Immutable storage, подпись |
| **Сессионные токены** | L2 | In Transit + In Use | Перехват даёт доступ к сессии | JWT + подпись, короткий TTL, TLS 1.3 |
| **Расписание врачей** | L4 | At Rest | Внутренняя информация | Базовое шифрование БД |
| **Прайс-лист услуг** | L4 | At Rest | Публичная информация | Не требует шифрования |

## 3. Инструменты защиты данных

### 3.1 Шифрование At Rest

| Инструмент | Назначение | Применение |
|------------|------------|------------|
| **PostgreSQL TDE** | Прозрачное шифрование БД | Patient DB, Medical DB |
| **AES-256-GCM** | Шифрование файлов и полей | Документы, сканы, медкарты |
| **HashiCorp Vault** | Управление ключами и секретами | Централизованное хранение ключей |
| **LUKS** | Шифрование дисков на уровне ОС | Серверы с данными |
| **AWS KMS / Azure Key Vault** | Управление ключами в облаке | Если используется облако |

### 3.2 Шифрование In Transit

| Инструмент | Назначение | Применение |
|------------|------------|------------|
| **TLS 1.3** | Шифрование HTTP-трафика | Все API, веб-порталы |
| **mTLS** | Взаимная аутентификация сервисов | Межсервисное взаимодействие |
| **WireGuard / IPSec VPN** | Шифрование внутреннего трафика | Связь между филиалами |
| **HTTPS Everywhere** | Принудительный HTTPS | Nginx/Traefik конфигурация |

### 3.3 Защита данных In Use

| Инструмент | Назначение | Применение |
|------------|------------|------------|
| **Memory encryption (AMD SEV / Intel SGX)** | Шифрование оперативной памяти | Критичные сервисы |
| **Secure Enclaves** | Изолированная обработка данных | Обработка PHI |

## 4. Средства автоматизированного контроля

| Средство | Назначение | Что контролирует |
|----------|------------|------------------|
| **HashiCorp Vault** | Secret Management | Ротация ключей, доступ к секретам |
| **Open Policy Agent (OPA)** | Policy as Code | Проверка политик доступа к данным |
| **Falco** | Runtime Security | Аномальное поведение, доступ к файлам |
| **SIEM (ELK/Splunk)** | Мониторинг безопасности | Анализ логов, алерты на инциденты |
| **DLP (Data Loss Prevention)** | Предотвращение утечек | Контроль исходящих данных |
| **Database Activity Monitoring** | Аудит БД | Все запросы к критичным таблицам |
| **Certificate Manager** | Управление сертификатами | Автоматическое обновление TLS-сертификатов |

## 5. Реестр программных и аппаратных средств защиты данных

### 5.1 Программные средства

| Категория | Продукт | Назначение | Лицензия |
|-----------|---------|------------|----------|
| **Шифрование БД** | PostgreSQL + pgcrypto | Шифрование полей и TDE | Open Source |
| **Управление ключами** | HashiCorp Vault | Централизованное управление секретами | Open Source / Enterprise |
| **TLS Termination** | Nginx / Traefik | HTTPS, TLS 1.3 | Open Source |
| **VPN** | WireGuard | Шифрованный туннель между филиалами | Open Source |
| **Хэширование паролей** | Argon2 / bcrypt | Безопасное хранение паролей | Open Source |
| **Мониторинг** | Prometheus + Grafana | Метрики безопасности | Open Source |
| **SIEM** | ELK Stack | Сбор и анализ логов | Open Source |
| **Аудит БД** | pgAudit | Логирование запросов PostgreSQL | Open Source |
| **Policy Engine** | Open Policy Agent | Контроль политик доступа | Open Source |
| **DLP** | OpenDLP / MyDLP | Предотвращение утечек | Open Source |

### 5.2 Аппаратные средства

| Категория | Продукт | Назначение |
|-----------|---------|------------|
| **HSM** | Thales Luna / AWS CloudHSM | Аппаратное хранение ключей |
| **Encrypted Storage** | Self-Encrypting Drives (SED) | Шифрование на уровне диска |
| **Network Security** | Firewall (pfSense / FortiGate) | Сетевая защита |
| **Backup Storage** | NAS с шифрованием | Защищённые резервные копии |

## 6. Матрица применения защиты

| Компонент системы | At Rest | In Transit | Контроль доступа | Аудит |
|-------------------|---------|------------|------------------|-------|
| Patient DB (PII) | AES-256 TDE | TLS 1.3 | RBAC | pgAudit |
| Medical DB (PHI) | AES-256 TDE | TLS 1.3 + mTLS | ABAC | pgAudit + SIEM |
| Audit DB | AES-256 | TLS 1.3 | Read-only | Immutable |
| File Storage | AES-256-GCM | TLS 1.3 | RBAC | Falco |
| API Gateway | — | TLS 1.3 | JWT + OAuth2 | Access logs |
| Межсервисное взаимодействие | — | mTLS | Service mesh | Distributed tracing |
| Резервные копии | AES-256 | TLS 1.3 | Ограниченный | Логирование |
| Внешние интеграции (лаборатория) | — | TLS 1.3 | API Keys + mTLS | Request logging |

## 7. Рекомендации по внедрению

1. **Приоритет 1 (немедленно):**
   - Включить TLS 1.3 для всех внешних соединений
   - Внедрить TDE для баз данных с PHI/PII
   - Настроить HashiCorp Vault для управления ключами

2. **Приоритет 2 (в течение месяца):**
   - Внедрить mTLS для межсервисного взаимодействия
   - Настроить pgAudit для аудита БД
   - Развернуть SIEM для мониторинга

3. **Приоритет 3 (в течение квартала):**
   - Внедрить DLP для контроля исходящих данных
   - Рассмотреть HSM для критичных ключей
   - Автоматизировать ротацию ключей и сертификатов
