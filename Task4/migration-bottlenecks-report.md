# Отчёт: Оценка узких мест при миграции

## 1. Анализ ситуации

### Текущая система (As-Is)
- **Архитектура:** Монолитная, файловый режим работы
- **Хранение данных:** Excel, PDF, JPG на файловом сервере
- **Бизнес-системы:** 1С Бухгалтерия, 1С Торговля (файловый режим)
- **Инфраструктура:** Один физический сервер Windows Server 2022
- **Интеграции:** ККМ через TCP/IP + OLE

### Целевая система (To-Be)
- **Архитектура:** Микросервисная с API Gateway
- **Хранение данных:** PostgreSQL с шифрованием, Data Lake
- **Новые системы:** Порталы, CRM, интеграция с лабораторией
- **Инфраструктура:** Kubernetes, контейнеризация
- **Интеграции:** REST API, TLS 1.3, mTLS

### Масштаб миграции
- 5-кратный рост объёма данных
- Открытие новых филиалов
- Переход на мобильные приложения

## 3. Диаграмма Исикавы — Категории и проблемы

### Основная проблема: Снижение производительности и доступности при миграции

### Категория 1: Инфраструктура

| Проблема | Описание | Влияние |
|----------|----------|---------|
| Недостаточная мощность серверов | Один физический сервер не справится с нагрузкой | Критическое |
| Отсутствие отказоустойчивости | Нет резервирования, единая точка отказа | Критическое |
| Сетевая инфраструктура | Локальная сеть не готова к микросервисам | Высокое |
| Отсутствие контейнеризации | Нет опыта работы с Docker/Kubernetes | Среднее |

### Категория 2: Программное обеспечение

| Проблема | Описание | Влияние |
|----------|----------|---------|
| Legacy 1С в файловом режиме | Сложность миграции данных, блокировки | Критическое |
| Отсутствие API у текущих систем | Нет возможности поэтапной миграции | Высокое |
| Несовместимость форматов данных | Excel → PostgreSQL требует трансформации | Высокое |
| Зависимость от Windows Server | Целевая система на Linux/K8s | Среднее |

### Категория 3: Данные

| Проблема | Описание | Влияние |
|----------|----------|---------|
| Качество данных в Excel | Дубликаты, ошибки, неструктурированность | Критическое |
| Отсутствие единой схемы данных | Разные форматы в разных файлах | Высокое |
| Миграция медицинских данных (PHI) | Требует шифрования и аудита | Высокое |
| Синхронизация во время миграции | Данные изменяются в процессе переноса | Среднее |

### Категория 4: Интеграции

| Проблема | Описание | Влияние |
|----------|----------|---------|
| ККМ через OLE | Устаревший протокол, сложно заменить | Высокое |
| Интеграция с 1С | Нет стандартного API | Высокое |
| Внешняя лаборатория | Требуется новый API-контракт | Среднее |
| Отсутствие ESB/Message Broker | Нет инструмента для оркестрации | Среднее |

### Категория 5: Персонал

| Проблема | Описание | Влияние |
|----------|----------|---------|
| Нехватка DevOps-компетенций | IT-отдел: 3 человека, нет опыта K8s | Критическое |
| Сопротивление изменениям | Сотрудники привыкли к Excel | Высокое |
| Обучение пользователей | 35 сотрудников нужно переучить | Среднее |
| Нехватка разработчиков | Нет команды для создания микросервисов | Критическое |

### Категория 6: Процессы

| Проблема | Описание | Влияние |
|----------|----------|---------|
| Отсутствие CI/CD | Нет автоматизации деплоя | Высокое |
| Нет процесса управления изменениями | Риск неконтролируемых изменений | Высокое |
| Отсутствие мониторинга | Нет инструментов отслеживания проблем | Среднее |
| Нет плана отката | При сбое некуда откатиться | Критическое |

## 4. Рекомендации по устранению узких мест

### Приоритет 1 — Критические (до начала миграции)

| # | Рекомендация | Проблема | Срок |
|---|--------------|----------|------|
| 1 | Развернуть инфраструктуру K8s (managed или on-premise) | Недостаточная мощность, отказоустойчивость | 2-4 недели |
| 2 | Нанять DevOps-инженера и backend-разработчиков | Нехватка компетенций | 2-4 недели |
| 3 | Провести аудит и очистку данных в Excel | Качество данных | 1-2 недели |
| 4 | Разработать план отката (rollback strategy) | Нет плана отката | 1 неделя |
| 5 | Перевести 1С в клиент-серверный режим | Legacy 1С | 1-2 недели |

### Приоритет 2 — Высокие (параллельно с миграцией)

| # | Рекомендация | Проблема | Срок |
|---|--------------|----------|------|
| 6 | Внедрить CI/CD pipeline (GitLab CI / GitHub Actions) | Отсутствие CI/CD | 1-2 недели |
| 7 | Разработать ETL-процесс для миграции данных | Несовместимость форматов | 2-3 недели |
| 8 | Создать API-адаптеры для 1С и ККМ | Отсутствие API | 2-4 недели |
| 9 | Внедрить Message Broker (RabbitMQ/Kafka) | Отсутствие ESB | 1-2 недели |
| 10 | Провести обучение сотрудников | Сопротивление изменениям | 1-2 недели |

### Приоритет 3 — Средние (после запуска MVP)

| # | Рекомендация | Проблема | Срок |
|---|--------------|----------|------|
| 11 | Настроить мониторинг (Prometheus + Grafana) | Отсутствие мониторинга | 1 неделя |
| 12 | Внедрить процесс Change Management | Нет управления изменениями | 2 недели |
| 13 | Заменить ККМ на современные с API | ККМ через OLE | 1-2 месяца |
| 14 | Миграция с Windows на Linux | Зависимость от Windows | 1-3 месяца |

## 6. Заключение

Миграция системы "Medikamente" с монолитной архитектуры на микросервисную сопряжена со значительными рисками в следующих областях:

1. **Инфраструктура** — требуется полная замена серверного оборудования и внедрение контейнеризации
2. **Данные** — низкое качество данных в Excel требует предварительной очистки
3. **Персонал** — критическая нехватка DevOps и разработческих компетенций
4. **Интеграции** — legacy-протоколы (OLE) требуют создания адаптеров

**Ключевые факторы успеха:**
- Поэтапная миграция с параллельной работой систем
- Найм квалифицированного персонала до начала миграции
- Тщательное тестирование и план отката
- Обучение и вовлечение сотрудников
