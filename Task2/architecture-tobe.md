# Целевая архитектура системы "Medikamente" (To-Be)

## Применение принципов Privacy by Design

### Принцип 1: Проактивный подход
- Внедрение системы управления рисками до начала обработки данных
- Автоматическая классификация данных при поступлении

### Принцип 2: Конфиденциальность по умолчанию
- Минимизация собираемых данных
- RBAC/ABAC контроль доступа по умолчанию
- Шифрование всех данных по умолчанию

### Принцип 3: Конфиденциальность в дизайне
- Централизованный IAM для всех систем
- API Gateway как единая точка входа
- Сквозное шифрование (end-to-end)

### Принцип 4: Полная функциональность
- Удобный портал для пациентов с защитой данных
- Быстрая работа системы при включённом шифровании

### Принцип 5: Комплексная безопасность (Full Lifecycle)
- Шифрование at rest и in transit
- Политики ретенции и безопасного удаления
- Аудит на всех этапах

### Принцип 6: Прозрачность
- Панель конфиденциальности для пациентов
- Логирование всех операций с данными
- Отчёты для регулятора

### Принцип 7: Уважение к пользователям
- Управление согласиями (Consent Management)
- Право на удаление данных
- Понятные формы согласия

## Новые компоненты архитектуры

### 1. Security & Privacy Layer

| Компонент | Назначение | Принцип PbD |
|-----------|------------|-------------|
| **IAM Service** | Управление идентификацией, RBAC/ABAC | #2, #3 |
| **API Gateway** | Единая точка входа, аутентификация, rate limiting | #3, #5 |
| **Encryption Service** | Шифрование данных, управление ключами (Vault) | #3, #5 |
| **Audit Service** | Логирование всех операций с данными | #5, #6 |
| **Consent Management** | Управление согласиями пациентов | #2, #7 |
| **Data Classification** | Автоматическое тегирование данных | #1, #3 |

### 2. Business Services Layer

| Компонент | Назначение |
|-----------|------------|
| **Patient Portal** | Личный кабинет пациента (запись, история, анализы) |
| **Reception Portal** | Портал для ресепшена (записи, напоминания) |
| **Medical Records Service** | Управление медкартами |
| **Appointment Service** | Управление записями к врачам |
| **Payment Gateway** | Обработка платежей (PCI DSS) |
| **Notification Service** | Уведомления (SMS, push, email) |
| **Laboratory Integration** | API-интеграция с лабораторией |
| **CRM** | Данные клиентов, история взаимодействий |

### 3. Analytics Layer (Privacy by Design)

| Компонент | Назначение | Меры защиты |
|-----------|------------|-------------|
| **Data Lake** | Хранение сырых данных | Шифрование, контроль доступа |
| **Anonymization Service** | Обезличивание данных для аналитики | K-anonymity, псевдонимизация |
| **BI Platform** | Отчёты и дашборды | Только агрегированные данные |

### 4. Data Storage Layer

| Компонент | Назначение | Защита |
|-----------|------------|--------|
| **Patient DB** | Данные пациентов (PII) | AES-256, TDE |
| **Medical DB** | Медицинские данные (PHI) | AES-256, отдельный контур |
| **Operational DB** | Операционные данные | Шифрование |
| **Audit DB** | Логи аудита | Immutable storage |

## Диаграмма контекста C4 (To-Be)

### Внешние акторы
- **Patient** — пациент (через портал/мобильное приложение)
- **Doctor** — врач
- **Administrator** — сотрудник ресепшена
- **Bookkeeper** — бухгалтер
- **Warehouse Keeper** — кладовщик

### Внешние системы
- **Laboratory** — внешняя лаборатория (API)
- **Payment Provider** — платёжный провайдер
- **SMS/Push Gateway** — сервис уведомлений

### Внутренние системы (новые)
- **Medikamente Platform** — основная платформа
  - API Gateway
  - IAM Service
  - Patient Portal
  - Reception Portal
  - Medical Records
  - Appointments
  - Payments
  - Notifications
  
- **Privacy & Security Services**
  - Encryption Service
  - Audit Service
  - Consent Management
  - Data Classification

- **Analytics Platform**
  - Data Lake
  - Anonymization
  - BI/Reporting

- **Legacy Systems** (сохраняются на переходный период)
  - 1С Бухгалтерия
  - 1С Торговля и склад
  - ККМ
